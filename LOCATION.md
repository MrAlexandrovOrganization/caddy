# HTTPS для мобильного Location

Публичный вход предназначен только для отправки координат с телефона.
DNS-имя `location.mralexandrov.duckdns.org` указывает на существующий HTTPS edge
Hostkey Russia. Его wildcard SNI-маршрут уже передаёт поддомены в этот Caddy;
конфигурацию VPN listener менять не требуется.

В приватном `caddy.env` на Russia включите:

```dotenv
LOCATION_INGRESS=location_mobile_site
LOCATION_DOMAIN=location.mralexandrov.duckdns.org
LOCATION_UPSTREAM=100.64.0.6:18084
```

По умолчанию, при отсутствии `LOCATION_INGRESS`, сайт выключен. Образец
`caddy.env.example` включает его с синтетическими адресами для `make check`.
Проверяется также выключенный вариант без домена и upstream.
Изменение environment требует штатного `make up`; `make reload` достаточно
для последующих изменений Caddyfile без новых переменных. Доставка исходников —
через Git и CI/CD этого проекта. Для отключения задайте
`LOCATION_INGRESS=location_disabled` и примените environment; сертификаты сохраняются.

## Граница API и авторизация

- Caddy выдаёт TLS-сертификат и пропускает только `PUT /mobile/locations/{uuid}`
  с каноническим UUID в нижнем регистре. Максимальный размер тела — 4096 байт.
  Все остальные пути и методы возвращают 404, включая чтение/удаление истории,
  legacy `POST /locations`, health, readiness и метрики.
- Заголовок `Authorization: Bearer …` передаётся существующему backend без
  перенаправлений. Location проверяет SHA-256 токена в constant time до обработки
  данных. Действует прежний токен устройства; в Caddy его копировать не нужно.
  При отсутствующем/неверном токене backend отвечает 401, при отключённом
  мобильном API — 503. Проверка выполняется на каждом запросе.
- Upstream доступен по tailnet между Russia и Finland. Телефону достаточно
  обычного интернета: пользовательский Tailscale больше не нужен для отправки.
  Старый внутренний адрес продолжает работать для прежних клиентов.
- Используется `safe_access`: объекты request/response с координатами, URL
  и заголовками авторизации исключены из access/error логов Caddy.
  Не включайте request/debug logging с реальными данными.

Проверка доставки: штатный CI `make check`; затем runtime TLS, 401 без токена
и с неверным токеном, 400 для невалидного тела с действующим токеном, 404 для
legacy API и методов чтения/удаления. Для проверки валидного токена используйте
пустое тело `{}`, чтобы не записывать синтетическую координату в историю.
После переключения телефона проверьте приём реальных Android-точек в БД.

## Настройка установленного Android-приложения

Новая версия APK не требуется: приложение уже поддерживает HTTPS.
В поле «Адрес сервера» укажите `https://location.mralexandrov.duckdns.org`
без порта и API-пути. Сохранённый токен менять или вводить заново не требуется.

Приложение блокирует смену адреса, пока есть неотправленные точки. Для перехода
сначала оставьте прежний VPN включённым и дождитесь пустой очереди. При
необходимости временно остановите запись, чтобы новые измерения не попали
между опустошением очереди и сохранением настроек; после смены адреса возобновите
запись. Остановка записи не удаляет накопленные данные.
Затем отключите Tailscale на телефоне и проверьте отправку по HTTPS.
В браузере корень нового домена возвращает 404: это вход API без веб-интерфейса.
